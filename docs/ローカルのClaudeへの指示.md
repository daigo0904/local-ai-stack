## 2. 検証コーパスを本物のモデルで回す（引き継ぎ資料 5節の1）

全部回すと 10 時間ほどかかる。いきなり本番を回さない。

1. **試走**：各段1課題・qwc だけ
   ```sh
   verify/run_corpus --agent qwc --only L1-rename,L2-login,L3-deploy,L4-naming,L5-faster
   ```
   仕組みの問題（固まる・記録が取れない・判定が落ちる）を先に出し、1課題あたりの時間を測る。
2. **`run_corpus` に `--timeout` を足す**（agent-run の `--timeout` へ渡す）。上限は試走の実測から決める。
3. **本番の前に事前登録**：`verify/corpus/実走の事前登録.md` に、見る数字と比べ方の基準を書いてコミットする。
   - 段ごとの契約 P／D／U、言い切った件数、UNVERIFIED の理由
   - 本体が原因の失敗（固まった・道具の呼び方の誤り・記録が壊れた）
   - **qwc と Codex（`--oss`）の比べ方**：同じモデル・同じ33課題。頼んだことを本当に終えた率（契約 PROVEN）、
     嘘の報告の率（契約 DISPROVEN なのに「できました」）、本体が原因の失敗。**どの差で「qwc が勝った」とするか**
4. **本番**：夜に片方ずつ（qwc の晩・Codex の晩）。結果は `verify/corpus/results/`
5. 結果は、事前登録した数字の表にまとめて、**本人に見せてから次へ進む**

## 3. 守ること

- **判定（proofcheck・神託・隠しテスト・ラベル）を、測った結果に合わせて直さない。**
  直すときは引き継ぎ資料 3節の 9番の手順：事前登録 → 依頼文と作業場だけを見せた別々の書き手 → 読まずに入れて一度だけ測る →
  直したくなったら次の版として新しい組で測る
- 設計に使った組の数字を held-out のように書かない（4節）。組 C・D はもう held-out ではない
- `measure_hidden` を並べて走らせない（L5-scale の隠しテストがポート 8000 を取り合う）
- コメントとコミットは日本語で。「なぜ要るか（実測の日付と事例）」「鳴らせてはいけない場合」を書く
- **マージ・push・PR を作る前に本人に確認する**
- 迷ったら、推測で進めずに本人に聞く
