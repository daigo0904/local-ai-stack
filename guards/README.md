# 見張り

Mac の上で動かしている AI 一式が、**落ちずに「黙る」**のを見つけて直す層。

`launchd` の `KeepAlive` はプロセスが死んだときにしか効かない。ところが実際に起きる壊れ方は、
どれもプロセスが生きたまま仕事だけ止まるものだった。

| 起きたこと | 外から見えた様子 |
| :--- | :--- |
| cloudflared のトンネルが死んだ | プロセスは生存・ログも出続け、**10時間気づかなかった** |
| ollama が答えなくなった | `/api/tags` は 200、`ollama ps` も「17GB・100% GPU」と正常表示 |
| gateway が詰まった | ポートは開いたまま |

だからこの一式は「立っているか」ではなく **「仕事ができるか」** を確かめる。

## 何を見ているか

```
        watchdog ──心拍──→ model-guard ──→ ollama（実際に1トークン生成させる）
           │  └──心拍──→ line-guard ──→ LINE の入り口（LINE自身に叩いてもらう）
           │                              gateway（落ちている）
           └────────────────────────────→ gateway（立っているのに黙る）
                                          ＋ line-guard が黙ったら肩代わり
```

| | 間隔 | 見るもの | 直し方 |
| :--- | :--- | :--- | :--- |
| `model-guard` | 2分 | ollama が本当に1トークン返すか | 2回失敗→実行体を落とす / 3回→ollama ごと入れ直す / 5回→知らせる |
| `watchdog` | 3分 | gateway の黙り・見張りたちの心拍 | `silent` 2回 / `degraded` 3回 で入れ直す（15分のクールダウン付き） |
| `line-guard` | 5分 | トンネル・中継・外からの到達性 | トンネルを張り直す。**先に「外に出られるか」を見る** |
| `qwc-guard` | 1日 | qwc が「頼んだら動くか」 | **直せない。知らせるだけ**（qwc は常駐していない） |
| `config-guard` | 呼ばれたとき | 設定が「戻せる形」にあるか | 動いた形に戻す（戻す前のものも残す） |
| `claw` | — | 入り口。`claw status` に見張り3つが出る | — |

## 入れ方

```sh
git clone <このリポジトリ> && cd 見張り
./install
```

`~/bin` にスクリプトを置き、`~/Library/LaunchAgents` に plist を作って登録する。
plist をテンプレートにしてあるのは、`launchd` が `~` を展開しないため。入れる人の HOME をここで埋める。

知らせ先は `~/.openclaw/.env` に置く（`.env.example` 参照）。無くても見張りは動くが、
直したことが誰にも届かなくなる。

```sh
./install --check      # 入っているか見る
./install --uninstall  # 外す
```

## 使い方

```sh
claw status            # 全体。見張り3つの心拍も出る（一瞬）
watchdog --report      # 中身まで確かめる
model-guard --report
watchdog --dry-run     # 調べるだけで手を出さない
```

普段は何も言わない。**直したときと、直せなかったときだけ** Discord に一言送る。

### 常駐しないものの見張り方

`qwc` は頼まれたときだけ動くので、「立っているのに答えない」という状態が無い。
代わりに見るのは **「いま頼んだら、ちゃんと最後まで動くか」**。
書き捨てのフォルダに合言葉を書いたファイルを置き、それを読ませて、

1. 合言葉が返事に入っているか（モデル・道具・指示の理解が通っているか）
2. そのファイルが**変わっていない**か
3. 頼んでいないファイルが**増えていない**か

を見る。2 と 3 を入れているのは、ここが壊れると黙って被害が出るため。
**「動くけれど勝手に書き換える」は、動かないより困る。**

**この見張りだけは直せない。**蹴り直す相手がいないので、できるのは知らせることだけ。
直せないものを直せるふりをしないため、復旧の段取りは置いていない。

## 設計で外せなかった判断

**プロセスは分ける。コードは分けない。**
4つが別プロセス・別の時計・別の判断で動いているからこそ、1つが黙っても他が気づく。
そこが独立の中身であって、**同じ文字列を別々に持つことではない。**

最初は逆にしていた。心拍のコードを4つに書き写し、「共通の部品が壊れると見張りが揃って黙るから」
と書き添えていた。実際に起きたのは逆だった。

- 書き写しを入れたその日のうちに、`watchdog` の編集で `beat` と `pulse_age` を巻き込んで消し、
  `NameError` で落とした。
- 同じ日に数えたら `env_value` は10ファイル、`notify` は6ファイルに増えていた。
- 4つの `beat` のうち `line-guard` だけ既に中身がずれていた。ずれていたのは
  **「わざと共有していない」と主張している説明文そのもの**だった。

いまは判断を含まない道具（ファイルの読み書き・通知・鍵）だけ `guardlib.py` に集めてある。
**「何を見るか」「いつ手を出すか」は各見張りが自分で持っている。**
そこを共有すると、1つの判断ミスが4つに同時に効く。

`guardlib.py` が単一障害点であることは認める。壊れれば4つとも起動しない。
代わりに `guardlib.py --selftest` を置き、`install` が入れるたびに走らせる。
**重複で守るのをやめて、検査で守るほうに替えた。**

**知らせは gateway を通さない。**
`discord.com` を直接叩く。gateway が死んでいるときにこそ知らせたいので、
死んでいる相手を経由してはいけない。

**担当を重ねない。**
gateway が「落ちている」のは `line-guard`、「開いているのに答えない」のは `watchdog`。
重なると2つが同時に入れ直して傷が広がる。ただし `line-guard` 自身が黙ったときだけ、
`watchdog` が3回目（9分）で肩代わりする。重ねないままだと「line-guard が死なない前提」になるため。

**すぐには手を出さない。**
入れ直しは必ず連続回数で判断する。gateway の再起動は Discord と LINE をいったん落とすので、
一度の失敗で切ると「直すつもりで壊している」ことになる。

## 設定を戻せるようにする（`config-guard`）

入れ直しても戻らないとき、次の手は **「設定を、動いた形に戻す」**。
原因の多くは設定で、決めてある形に戻すのがいちばん結果の読める手当てになる。

```sh
config-guard              いまの状態
config-guard --save       いまの設定を「動いた形」として記録する
config-guard --diff       動いた形から何が変わったか
config-guard --rollback   動いた形に戻す
config-guard --log        これまでの記録
```

`~/.openclaw` を git で追う。**118MB のうち追うのは設定の 48KB だけ**で、
既定で全部無視し、設定だけを名指しで拾う。除外を並べる形にすると、
あとから増えた会話履歴やキャッシュが黙って入るため。
**ここは手元だけに置き、どこにも push しない**（自分を指すIDが実物のまま入っている）。

### 「動いた形」は、動いたことを確かめてから

ただ保存した設定ではない。**その設定で受け口が実際に応答したこと**を確かめてから印を付ける。
動かない設定に戻しても意味がない。印を更新するのは `watchdog` が「今日も元気だ」と
確かめた日に1回だけで、**動いていることを確かめられるのは、その瞬間しかない。**

### 戻すとき、いまのものを捨てない

戻す前に、壊れている今の設定も必ず記録してから戻す。
「戻したら、何が悪かったのか分からなくなった」を避けるため。

### 判断で直そうとしない

ここでやるのは「決めてある形に戻す」だけ。考えて直すのは、この先の段で人か qwc がやること。
決定論的に戻せる手段を先に用意しておかないと、その先を安全に足せない。

### 見張りどうしは、判断を借りない

`config-guard` は受け口の応答を **`watchdog` に聞かず、自分で叩く**。
最初は聞く作りにしていて、`watchdog` が元気なときに `config-guard --save` を呼び、
その `--save` が `watchdog --check` を呼び…… と互いを呼び合って止まらなくなった。
見張りどうしは心拍だけを見て、判断は各自で持つ。

## 見張りに証明させる（`guard-drill`）

見張りは黙って壊れる。実際、`watchdog` は直っていないのに「入れ直した」とログに書いていた。
**黙って壊れた見張りは、健全な見張りと見た目が同じ。**この一式が扱っている問題が、
見張り自身に返ってきている。だから「動くはず」ではなく「動くことを見せろ」に切り替える。

```sh
guard-drill          安全な訓練だけ（サービスは止めない）
guard-drill --full   止まる訓練も含めて全部
guard-drill --list   何を試すか見る
```

| 訓練 | 何を壊す | 実測 |
| :--- | :--- | :--- |
| `pulse` | 心拍を巻き戻し、相互監視が蹴り起こすか | 即時 |
| `lock` | 二重に走らない鍵が効くか | 0.03秒で引き返す |
| `guardlib` | 共有部品の写しを壊し、検査が落とせるか | 即時 |
| `qwc` | 偽物にすげ替え、4通りの壊れ方を見分けるか | 即時 |
| `ollama` | 頭脳を本当に止める ※ | **40秒**で気づいて手を出す |
| `gateway` | 受け口を黙らせる ※ | **43秒**で気づいて入れ直す |
| `config` | 設定を壊して起動不能にする ※ | **68秒**で戻して復旧、壊れた形も残す |

※ はサービスが一時的に止まるので `--full` のときだけ走る。

### 訓練が障害にならないための決まり

1. 壊す前に、戻し方を先に決める。決められないものは訓練にしない。
2. どの項目も、終わったら**戻ったことを確かめる**。確かめずに次へ進まない。
3. 途中で失敗したら、そこで止めて全部戻す。残りは走らせない。
4. 走っているあいだは印を置く（`drill-in-progress`）。記録を読む人が本物の障害と取り違えないため。
5. **合否に「後始末の確認」を含める。**壊したまま「通った」と出すのが一番危ない。

### 合否は「見張りの記録」で決める

サービスが戻ったことだけを見ていると、**訓練の後始末で戻したぶんを「見張りが直した」と取り違える。**
実際そうなり、見張りが1行も記録していないのに「通った」と表示した。
いまは訓練の前後で見張りのログを比べ、**気づいた形跡と手を出した形跡の両方**が無ければ落とす。

## つまずいた記録

実測で分かったこと。同じ罠を踏まないように残しておく。

- **`launchd` の PATH は `/usr/bin:/bin:/usr/sbin:/sbin` しかない。**
  `openclaw` は `#!/usr/bin/env node` なので、そのままでは `env: node: No such file or directory` で必ず失敗する。
  見張りが黙って無力になる典型。絶対パス＋PATH 追加で塞いである。
- **`launchctl kickstart` は plist が外れていると効かない。**
  `Could not find service` で失敗するだけ。戻り値を捨てていたせいで、直っていないのに
  ログにだけ「入れ直した」と書き残っていた。**嘘をつく見張りは、居ないより悪い。**
  いまは `bootstrap` で読み込み直し、ポートが開くまで待って確かめてから記録する。
- **同時に2つ走ると二重に入れ直す。** 手動実行と定期実行がぶつかり、両方が「連続3回」と数えた。
  `fcntl.flock` の鍵で、取れなければ 0.04 秒で引き返す（`--report` `--check` `--dry-run` は鍵を取らない）。
- **停止したプロセスもポートは握ったまま。** 訓練の合否に `port_open` を使っていて、
  止めた相手が常に「開いている」と出ていた。**この一式が存在する理由そのものを、訓練の中で間違えていた。**
- **シグナルは番号で送らない。** macOS は `SIGSTOP=17` / `SIGCONT=19`、Linux は `SIGSTOP=19` / `SIGCONT=18` で逆。
  Linux の 19 を「止める」つもりで書いていたので、実際には「動かす」を送っていた。
  訓練は何も壊さないまま「通った」と報告していた。
- **記録が伸びたかだけで待つと、途中の「連続1回」で次へ進んでしまう。**
  手当てまで見届けたいなら、その結末の一行が出るまで待つ。16秒で誤って落ちた。
- **見張りどうしが判断を借りると、呼び合って止まらなくなる。**
  `watchdog` が `config-guard --save` を呼び、その `--save` が `watchdog --check` を呼んだ。
- **相手が黙っているあいだ、見張りは点検の時間切れ（最大90秒）ずっと鍵を握る。**
  訓練が同じ時間に呼ぶと黙って引き返すので、そのぶんを「試した」と数えてはいけない。
- **「仕事中」と「固まり」は CPU で分かる。** 生成中の `llama-server` は 7〜84%、待機・固まりはちょうど 0.0%。
  ollama は `-np 1`（同時1件）なので、他人の依頼待ちを固まりと誤診すると動いている仕事を壊す。
- **`llama-server` だけ止めても障害は再現しない。** ollama が自力で積み直す（実測26秒）。
  再現するには `ollama serve` 本体ごと止める。
- **`openclaw health` の `degraded` は一時的。** 20秒ほどで自分で `ok` に戻る（`max` も 11769ms→23ms）。
  即入れ直すと治りかけを毎回切ることになる。

## できないこと

- **見張りが全部同時に黙ったとき。** 3つが互いを見ているので確率は下がるが、ゼロにはならない。
- **Mac ごと落ちたとき。** 中の誰にも気づけない。外の機械が要る。

できないことははっきり分けてある。ここを曖昧にすると「見張っているつもり」が一番危ない。
