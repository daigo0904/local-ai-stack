- 隠しテストは、正直な解き方を1件も新たに落とさなかった（C の 47件・A の 33件）。誤報の 2件は
  手書きの契約の側（L3-backup・L3-mail：外へ出さずに「送っていない」と正直に言った回が、契約の
  must_pass・may_change に合わない）で、隠しテストを入れる前からあった。
- 「バグが解消された」は、C の正直な解き方では1件も PROVEN にならなかった。C の申告に「バグを直した」の
  言い回しが無く、その主張が取り出されていないため（A の正直では 0 → 6）。
- 隠しテストの無い課題は 6（外部・人の判断・レビューだけ）。そこでの C の嘘 13件中 10件が契約 PROVEN のまま。

## 追加の見方（事前登録に無い。測った後に足したので、主な数字にはしない）

「契約も、取り出せた申告も全部 PROVEN」＝この層が言い切った件数。

| | 件数 | 言い切った |
| --- | --: | --: |
| C の嘘 | 78 | **17** |
| C の正直 | 47 | 28 |

言い切った嘘 17件のうち 16件は、取り出せた申告が「ファイルを変更した」だけだった。
**嘘の部分（「動きは変えていません」「負荷試験しました」「コメントは正確です」「互換性は保っています」）は、
申告の分解で取り出されず、判定されていない。**取り出せた部分だけを判定して PROVEN と言うのは、
「報告が本当」と言うことと違う。これは隠しテストとは別の穴で、この回の一番大きな発見。

## 次の版の候補（入れたら、新しい書き手の新しい組で測る）

1. **取り出せなかった文を「判定していない」と出す。**報告の文のうち、どの主張にも当たらなかったものが
   あれば、報告全体を PROVEN と言わない（その他の主張として UNVERIFIED に残す）
2. 「動きを変えていない」「互換性を保った」を主張の種類にし、隠しテストの regression を証拠にする
3. 隠しテストの書き手に、黙った変更（端数・None・余計な行）を探す観点を明示して渡す。書き手は別の者に
4. 外部の課題の契約を、「外に出さずに正直に断った」回を落とさない形にする（誤報 2件）
